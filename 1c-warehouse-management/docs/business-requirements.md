# Бизнес-требования

## 1. Контекст

Небольшая торговая компания закупает товары у поставщиков, размещает их на складах и продает покупателям. Система должна фиксировать складские операции и не допускать проведения реализации при недостаточном количестве товара.

## 2. Роли пользователей

| Роль | Основные действия |
|---|---|
| Кладовщик | Создает поступления, перемещения и списания |
| Менеджер продаж | Создает документы реализации |
| Администратор | Ведет справочники, проверяет данные и формирует отчеты |

В демонстрационной версии разграничение прав описывается как требование; настройка ролей в метаданных будет отдельной задачей.

## 3. Основные справочники

- **Номенклатура:** наименование, артикул, единица хранения, признак активности.
- **Склады:** наименование, комментарий.
- **Контрагенты:** наименование, ИНН (строка), контактная информация.

## 4. Документы

### ПоступлениеТоваров

Реквизиты: склад, поставщик, дата, комментарий.

Табличная часть Товары: номенклатура, количество, цена, сумма.

При проведении формирует приход по регистру ТоварныеОстатки.

### РеализацияТоваров

Реквизиты: склад, покупатель, дата, комментарий.

Табличная часть Товары: номенклатура, количество, цена, сумма.

Перед проведением проверяет наличие товара. Если хотя бы по одной позиции недостаточно остатка, проведение отменяется. Проверка должна учитывать суммарное количество одинаковой номенклатуры в разных строках одного документа.

### ПеремещениеТоваров

Реквизиты: склад-отправитель, склад-получатель, дата, комментарий.

Табличная часть Товары: номенклатура, количество.

При проведении формирует расход со склада-отправителя и приход на склад-получатель. Перемещение между одним и тем же складом запрещено.

## 5. Бизнес-правила

1. Склад должен быть заполнен в складских документах.
2. Номенклатура в каждой строке обязательна.
3. Количество должно быть больше нуля.
4. Реализация не может уменьшить остаток ниже нуля.
5. При перемещении склады-отправитель и получатель должны различаться.
6. Пустой документ не проводится.
7. Денежные суммы рассчитываются как количество × цена; правила округления фиксируются при реализации денежной части.

## 6. Критерии приемки

- Поступление увеличивает остаток на выбранном складе.
- Реализация уменьшает остаток.
- Реализация с недостаточным остатком не проводится.
- Проверка учитывает повторяющиеся товары в табличной части.
- Перемещение изменяет остатки двух складов на одинаковое количество в противоположных направлениях.
- Отчет показывает остатки в разрезе склада и номенклатуры.
